# 🛡️ ScamShield AI

**Explainable machine learning for online scam-risk screening.**

ScamShield AI combines:
- An SMS spam/ham classifier trained with TF-IDF and scikit-learn.
- A transparent, rule-based URL structure analyzer.
- A Streamlit dashboard for message checks, URL checks, batch CSV analysis and model evaluation.

> **Important limitation:** The message model is trained on an SMS spam dataset, not on every category of financial scam. URL analysis is heuristic, not a trained phishing classifier. A negative result does not prove safety.

## Features

- Message classification using Logistic Regression and Multinomial Naive Bayes comparison.
- URL structural indicators (no URL is opened or fetched).
- Explainable indicators and general safety guidance.
- Batch CSV analysis using a `message` column.
- Held-out evaluation metrics and confusion matrix.
- Unit tests for basic URL parsing and prediction behavior.

## Architecture

`Input → validation → text model OR URL heuristic analyzer → explanation → Streamlit UI`

## Tech stack

Python, Pandas, scikit-learn, TF-IDF, Logistic Regression, Multinomial Naive Bayes, joblib, Streamlit and Plotly.

## Dataset

Download the UCI SMS Spam Collection:
https://archive.ics.uci.edu/dataset/228/sms+spam+collection

Extract the `SMSSpamCollection` file to `data/SMSSpamCollection`. The raw dataset is not included in this repository. Its labels are `ham` and `spam`; these labels should not be described as a perfect measure of all scam types.

## Run locally

### 1. Create and activate a virtual environment

Windows:
```bash
python -m venv .venv
.venv\Scripts\activate
```

macOS/Linux:
```bash
python -m venv .venv
source .venv/bin/activate
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Add the dataset and train

Place the extracted `SMSSpamCollection` file at `data/SMSSpamCollection`, then run:

```bash
python -m src.train_model
```

This trains both baseline models, compares spam F1 and recall, then saves:
- `models/message_model.joblib`
- `models/metrics.json`

These generated artifacts are ignored by Git by default. For deployment, either include the small model artifact if appropriate for your repository and hosting constraints, or use a documented secure artifact-download step. Do not commit sensitive data or secrets.

### 4. Launch the app

```bash
streamlit run app.py
```

### 5. Run tests

```bash
python -m unittest discover -s tests -v
```

## Deploy

A straightforward option is Streamlit Community Cloud:
https://docs.streamlit.io/deploy/streamlit-community-cloud

Ensure the model artifact is available in the deployed environment. If the artifact is absent, train it before deployment or implement a documented artifact retrieval step.

## Evaluation

The training script reports:
- Accuracy
- Spam precision
- Spam recall
- Spam F1-score
- Confusion matrix

Use the actual metrics generated by your experiment in your report. Do not invent accuracy claims. The held-out test results are not a guarantee of real-world performance.

## Safety and privacy

- Do not enter passwords, OTPs, payment PINs or private financial information.
- The app does not open submitted URLs.
- HTTPS does not guarantee legitimacy.
- URL heuristics can flag legitimate links and miss malicious links.
- Avoid storing user-submitted content or committing private data.
